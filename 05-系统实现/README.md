## 这次相对上一版的变化

- 默认首页为计划表，不是大屏；每次创建真实写入SQLite，可展开任务历史。
- 同一份计划在二级工作空间完成基本信息、输入、约束目标、计算仿真、方案分析、确认提交，不把步骤拆成菜单。
- 不同演示身份在服务端按角色、工厂过滤数据并限制操作，前端相应显示菜单。
- Mock JSON作为输入调用真实Python算法，指标与事件日志来自计算，不是写死的卡片。
- 后台线程执行任务，状态和阶段写入数据库；离开页面可回来查看，重启时中断任务标失败不永久卡住。
- 方案比较、车间事件、资源/切换/交付指标与确定性解释；未接大模型，不称LLM生成。
- 只有通过已实现规则并且无未排车辆的方案可提交；主管批准只写入本地研究状态，不发布生产。

## 演示身份

| 身份 | 菜单与数据范围 |
|---|---|
| planner-a | 计划管理，F1，创建/配置/计算/提交 |
| planner-b | 计划管理，F2，不能读取F1计划与任务 |
| manager | 计划管理、待办，F1/F2，可批准 |
| engineer | 计划管理、规则资源，F1；只读业务计划 |

注意：`X-Demo-User`是为演示提供的身份选择头，不是生产SSO。后端权限隔离真实执行，但任何本地使用者都可选择演示身份。服务只绑定127.0.0.1，不应部署为公开生产服务。

## 演示路径

1. 以planner-a打开“计划管理”，新建W+3计划并选择F1。
2. 在“接口输入”载入服务端样例，保存输入；可上传修改后的Mock JSON。
3. 查看/配置引擎实际支持的参数，不能把未实现规则通过自由文本假装生效。
4. 发起计算。可离开页面，任务继续执行；返回查看真实计算阶段与历史。
5. 在方案分析比较baseline和optimized、检查已实现约束校验、未排及延期、事件时间与指标。
6. 选定可提交方案，确认提交；切换manager，从待办进入批准。
7. 切换planner-b，验证看不到F1计划；管理员仅查看技术运行。

已创建的“一工厂 · Mock周计划验证”是浏览器验收保留的150车样本计划，可直接打开分析。

## 边界

当前专用计算支持W+3短期研究模型。N+1/N+3/N+6可建计划但不允许运行短期引擎冒充其专用算法；长期聚合与跨层联动仍待实现。

不包含原说明书全部工艺规则、人工冻结/已投产保护、真实工厂缓存流转与停机、工厂间资源调度、多版本变点/风险预警完整台账，以及生产发布回执。当前三车间简化仿真不能直接预测真实工厂准确率。

本次能验证模型内部守恒、时序、资源约束、可重复性和同目标改善。要验证现实预测精度，仍需工厂实绩、参数标定和独立留出样本。没有这些证据，不承诺“准确率95%”或其他收益比例。
