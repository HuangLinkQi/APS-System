# APS 计划与排程平台 · 前端

企业操作型界面（非原型演示）：一级计划列表 + 二级计划工作空间（6 步）。
零依赖原生 JS / CSS / HTML，无 npm、无 CDN、无外部图表库，调用本机后端 API。

## 运行

后端 `server.py` 直接托管本目录（`directory=aps-v2/web`），默认端口 18744：

```bash
cd aps-v2
python3 server.py            # http://127.0.0.1:18744
```

打开 `http://127.0.0.1:18744/` 即可。前后端不同端口时，可在「系统」页设置 API 基地址（存浏览器本地）。

## 一级：计划管理

- 列表：名称 / 类型 / 工厂 / 状态 / 输入 / 任务数 / 结果 / 更新时间；搜索与类型筛选只影响展示。
- 展开行查看历史计算任务（任务由服务端保存，离开页面不中断）与结果概要。
- 计划类型 W+3 可运行真实计算；N+1 / N+3 / N+6 明确标注「计算未实现」，按钮禁用，不会套用 W+3 算法伪造结果。

## 二级：6 步工作空间

1. **基本信息**：创建计划（名称 / 类型 / 工厂）写入后端；创建后类型与工厂不可变更（接口未提供）。
2. **接口输入**：JSON 编辑、上传 Mock 文件、载入 `GET /api/sample`、格式化、保存。保存会清除已有计算结果，任务历史保留。
3. **约束目标**：只维护引擎真正解析的字段 —— `calendar`（工作日/班次/单班秒数/加班/日车辆上限）、`supply`、`changeover`、`process_times`、`transfer_seconds`、`seed`、`time_limit_seconds`、`drain_days`；`orders` 与 `supply` 明细在步骤 2 编辑。目标层级为引擎固定声明，只读。**不提供会被静默忽略的自由 JSON（如自造的 constraints / objectives）**；若输入含引擎不识别的字段，页面会点名列出并说明其不生效。
4. **计算仿真**：发起 `/run` 后轮询 `/api/tasks/{id}`，显示服务端阶段与进度日志，**不显示虚构百分比**；可停止刷新、可离开页面回列表继续。
5. **方案分析**：首屏 6 项核心指标（已排 / 准时 / 切换损失 / 完工跨度 / 未排 / 独立模型校验）→ 事件甘特（HTML/CSS）→ 折叠的详细指标与目标层级、分日负荷、逐车序位、统一校验、未排原因、搜索候选、引擎边界、确定性说明助手、原始结果 JSON（超 120KB 自动截断并提供下载）。
6. **确认提交**：展示选定方案与阻断项，页内二次确认后提交；提交前明确提示演示环境不接生产。

审批在主管的「待办审批」页执行（页面内确认，不使用原生 `confirm`）。

## 结果归一化

`app.js` 第 9 节 `normalizeResult()` 是唯一的结果结构映射点，输入为 `engine/solve.py` 的 `solve()` 返回值：

- 候选：`baseline` / `optimized`（提交时服务端只接受这两个键）。
- 指标：`plan.metrics` 的全量标量 + 分阶段字典（切换、等待、利用率），字段存在但为 `null` 显示「不适用」，字段缺失显示「未提供」。
- 甘特：由 `schedule.days` × `events` 聚合（阶段 × 计划日）。
- 校验：`validation.checks`；未排：`unscheduled`（原因码译中文，保留引擎明细）。
- 目标层级：`comparison.tiers / delta / improved_tiers`。
- 边界：`meta.rule_scope`、`assumptions`、`caveats`、`warnings`、`runtime`。
- 无法识别结构时返回 `null`，界面只展示原始 JSON 与说明，不臆造任何指标。

## 能力边界（界面如实呈现，勿当作已实现）

- 演示环境，未接入 ERP / MES；提交、批准都不会下发生产指令，也不代表真实生效范围。
- 计算内核为研究模型：**未实现人工冻结、冻结区与已投产保护**，也未实现钢铝比例、颜色批次、涂装缓存重排等完整原文工艺；请勿输入真实已投产或冻结订单。
- 校验是独立模型校验，不代表全厂完整工艺规则；未实现的约束不会因显示「通过」而满足。
- 方案说明助手为本地确定性规则问答，**未接入任何大语言模型**，只依据结果字段作答。
- 未实现发布、回执、对账与生效流程。

## 验证记录（2026-09-18）

以本机后端（隔离数据库）跑通：创建计划 → 载入样例 → 保存输入 → 步骤 3 修改真实字段（workdays、求解时限、按车型节拍）并保存 → 发起计算并轮询至完成 → 结果归一化（2 候选、40 项指标、3×N 甘特、11 项校验、0 未排）→ 页内确认提交 → 主管批准；同时验证非 W+3 计划 `/run` 返回 422、工程师 PATCH 返回 403、工厂数据隔离、静态资源由后端同源托管。渲染层以最小 DOM 环境对全部页面与 6 个步骤做过无异常检查；未做浏览器视觉验收与多尺寸适配验收。
